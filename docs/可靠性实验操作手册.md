# 独立实验与恢复 Runbook

## 准备

要求 Docker Desktop/Linux Docker、Python 3.11+ 和 NVIDIA CUDA GPU。公开 fixtures 是四句 Microsoft Huihui Desktop 合成语音，已包含在 experiments/fixtures，无需在 Linux 上安装该声音。需要重生成时可运行 Windows 的 `experiments/create_fixtures.ps1`，声音/音频哈希有变化时应视为新样本。

```bash
pip install -r requirements-dev.txt
python tools/prepare_lab.py
docker compose -f experiments/compose.lab.yaml build
docker compose -f experiments/compose.lab.yaml up -d
docker compose -f experiments/compose.monitoring.yaml up -d
```

模型默认 small，缓存到 models。已有离线模型时通过环境变量 `LAB_ASR_MODEL_PATH` 指定 **容器内**路径。此机器的镜像/模型缓存示例位于 experiments/local-cache.env.example，可用 `docker compose --env-file ... -f ... up -d`；缓存镜像仅是本机加速路径，第三方应从源码 build。

默认应用不需改环境：ASR 8001、API 8000；实验使用 ASR 18001、API 18000、Flink 18081、Kafka 39092、Prometheus 18090。实验数据在 data/reliability_lab，Redis 为 streamsense-lab_redis-data，网络和容器与默认部署隔离。Flink 实验 checkpoint=5s，默认仍为30s。先确认 `/jobs` 为 RUNNING 且 `/jobs/<id>/checkpoints` 有 completed，再运行故障。

## 复现

```bash
python tools/reliability_lab.py capacity --count 24 --output benchmarks/reliability/20261001/capacity.json
python tools/reliability_lab.py asr --count 40 --output benchmarks/reliability/20261001/fault-asr.json
python tools/reliability_lab.py flink-taskmanager --count 40 --output benchmarks/reliability/20261001/fault-flink-taskmanager.json
python tools/reliability_lab.py kafka --count 40 --output benchmarks/reliability/20261001/fault-kafka.json
python -m tools.reliability_report
python -m tools.reliability_report --check
```

每轮依次执行，不要并行改变同一栈。实验停止目标先查询并校验 `com.docker.compose.project=streamsense-lab`，只允许这三个服务；finally 会恢复被停服务。生产者确认每个输入 offset，瞬时失败重试并记录。故障后的未知 lag 不填零；非空但没有 committed offset 的分区仍为 unknown。

复测请使用新的输出目录以保留既有记录；报告工具可接受 `--directory`。20261001 目录是已发布基线，命令展示默认位置，复测修改输出参数后再生成报告。`plot_reliability.py` 需要额外安装 matplotlib，可从 summary 和原始采样重新绘图。

## 失败片段恢复

1. 查询 ASR `/health` 的 model_loaded、Flink 作业和 completed checkpoint；先处理模型路径/CUDA/网络问题。
2. 核对输入 manifest 与 `/api/reliability/segments?run_id=...`；status=error 是已捕获失败，不能等同于缺失。
3. 执行 `python -m tools.replay_failed --input benchmarks/reliability/20261001/fault-asr.json` 查看计划；确认服务健康后加 `--apply` 执行。仅连接隔离实验 broker，保留原始 stream/run/segment ID 和时间戳；失败状态可升级为成功。
4. 复核最终原始结果、逻辑重复和 lag。补偿结果写到独立 replay-asr.json，初始实验不改写；人工恢复没有被算作原始成功率。

## 停止

```bash
docker compose -f experiments/compose.monitoring.yaml stop
docker compose -f experiments/compose.lab.yaml stop
```

保留数据与卷便于复核。不要使用默认项目的容器名做故障。实验未证明 broker 数据盘丢失、JobManager 丢失或多节点 HA；checkpoint 本地文件只用于同机演练。PyFlink 存储配置使用 [FileSystemCheckpointStorage](https://nightlies.apache.org/flink/flink-docs-release-1.18/api/python/reference/pyflink.datastream/api/pyflink.datastream.checkpoint_storage.FileSystemCheckpointStorage.html)，不是把字符串直接传给 CheckpointConfig。
