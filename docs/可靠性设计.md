# 原始结果、重试与交付语义

## 修复的实际缺陷

1. Flink 重试耗尽的兜底结果曾没有 status，调用者默认成 ok。现在失败明确为 error 并进入失败 Topic；请求响应必须是含 status=ok 的对象。
2. 原来退避固定800ms，与说明不一致。现在 transient 错误使用800/1600ms指数退避，最多三次调用；4xx（408/429除外）不做无效重试，延迟上限30s。
3. 原句子表的去重键包含 text，不能作为原始片段重放身份。新增 SQLite raw_results 的 `(stream_id,run_id,segment_id)` 主键，首次成功为 canonical；相同 ID 即使转写稍变也不会再入一个逻辑结果。失败后的成功补偿允许升级。
4. API 原来的自动 offset commit 可能先于持久化。现在先保存原始结果、尝试句子投影、标记处理，再手动 commit。无效消息按 broker topic/partition/offset 生成稳定失败身份，避免毒消息无限卡住消费。

## 崩溃点与保证

| 崩溃位置 | 恢复行为 |
|---|---|
| 原始结果持久化前 | offset 未提交，Kafka 重投 |
| 原始结果已持久化、processed=0 | 重投恢复 canonical 内容，再尝试投影 |
| processed=1、commit 前 | 重投增加 deliveries，但不再处理同一原始结果 |
| 失败后补偿成功 | 原始账本替换为成功，保留失败历史和单独补偿证据 |

保证范围是原始账本唯一结果与明确失败；不能推广为所有输出 exactly-once。句子缓冲在内存中，Redis/JSONL/关键词 Kafka 是独立副作用。投影中途崩溃可重复，API 在仅加入缓冲后提交也可能使未刷句子需要从 raw_results 重建。原始结果包含文本、分段、时间与状态，始终独立可导出/重放。

Flink 默认已有30s checkpoint；新环境变量允许间隔和 FileSystemCheckpointStorage，实验配置5s，source state 的恢复仍与 HTTP/输出结果账本分开。Kafka Sink 保留 AT_LEAST_ONCE。来源：[Flink checkpoint 文档](https://nightlies.apache.org/flink/flink-docs-release-1.18/docs/dev/datastream/fault-tolerance/checkpointing/)。
