# 字幕精度与性能评测口径

## 字符与 token

参考文本由人工核对或固定合成语音脚本提供。两者来源分别注明，合成四句的 CER 不代表自然会议语音精度。

沿用 `tools/evaluate_subtitles.py`：去字幕时间码、序号、HTML 标记、方括号说明和短圆括号说明；统一部分全半角标点；压缩空白，中文之间空格删除。CER 删除所有空格，但**保留标点与英文字母大小写**。词级 tokenizer 将连续 ASCII 字母/数字视为词、汉字逐字分割；所以中文 WER 只是该混合 tokenizer 的辅助结果，不是基于中文分词器的词错误率。

Levenshtein 编辑数 = 插入+删除+替换。现有兼容公式 `distance / max(reference_length,1)`：空参考与空候选为 0，空参考有输出则为插入数量；该值不能解读为普通百分比，需要作为静音幻觉插入数单列。非空参考允许 CER/WER>1，不截断。

`tests/test_reliability.py` 将**同一份归一化与 token 序列**喂给 jiwer 4.0，逐例交叉验证编辑数，覆盖空参考、幻觉、标点、大小写和中英混合；没有通过换一种 normalization 让两个实现看似一致。

## 两种性能实验必须分开

- 旧视频测试：2 路 230 段是视频链路基线；4 路 39 段只跑 60 秒，是冒烟样本，不能作为完整容量点。
- 新 ASR 容量：固定四句合成音频循环 6 次，1/2/3/4/6 个 HTTP worker，每档 24 请求，small/cuda/float16/beam=5，warmup 排除；测 HTTP 时延、逐请求锁 wait/hold、排队数、吞吐和同样本 CER。它覆盖 ASR 服务，不覆盖视频 VAD、Kafka 与 API。
- 新故障演练：真实 Kafka→Flink→GPU ASR→API→SQLite，固定每组 40 个输入，在输入持续时停/启一个隔离容器，记录生产者 ACK、结果账本、checkpoint、lag 和状态变化。

P50/P95/P99 使用排序后 `(n-1)q` 的线性插值；总吞吐=count/该档墙钟秒数。高分位短样本只能用于本次比较。端到端时间截止 Flink 完成，API 收到时间用于恢复事件；句子等待时间另由原看板展示。

原始 JSON 记录样本哈希、模型路径、镜像 ID、代码 SHA256、warmup、每次请求/回答。`python -m tools.reliability_report --check` 校验摘要与原始数据哈希；不把历史平均值伪装成历史逐片段锁等待数据。
